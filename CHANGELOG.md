# Changelog

All notable changes to FABLEWRIGHT are recorded here. This project follows
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [1.0.0] - 2026-09-03

First release. Dual-host orchestration for Claude Code and OpenAI Codex.

### Added

- **The routing contract.** `skills/fablewright/SKILL.md` plus five references:
  `call-sheet.md` (how the wright decides, and the delegation test that usually says
  no), `role-contracts.md` (the five-part specification, per-lane prompts, the reader
  and ensemble contracts), `operations.md`, `hosts.md`, and `providers.md`.
- **Five routes.** `solo`, `delegate`, `audit`, `full`, and `ensemble`, declared on a
  machine-auditable `FABLEWRIGHT CALL SHEET` before the first task tool call. `solo` is
  the default; a later sheet may only escalate, and only on recorded new evidence.
- **Six pinned lane profiles** in `hosts/codex/agents/`: `luna` (gpt-5.6-luna, max),
  `terra` (gpt-5.6-terra, xhigh), `flash` (deepseek-v4-flash), `glm` (glm-4.6), and
  read-only reviewers on `gpt-5.6-sol` (xhigh) and `glm-4.6`.
- **Two Claude Code subagents.** `fablewright-reader` and `fablewright-scout`, both
  declared `tools: Read, Grep, Glob` so read-only is enforced by tool set rather than
  requested from a sandbox.
- **Three slash commands.** `/fablewright:preflight`, `/fablewright:route`, and
  `/fablewright:read`.
- **`scripts/ask-wright.sh`** — one hermetic, non-persistent Claude Code call that
  proves a Fable model actually answered before returning anything, by reading
  `modelUsage` from the structured result. Refuses a substitute wright.
- **`scripts/cast-call.sh`** — dispatches a lane through `codex exec` using the lane
  profile as the single source of truth, then verifies observed model, effort, provider
  and sandbox against the pin. A mismatch stops the lane rather than returning
  unverified work. Resolves the provider from `--provider`, then the lane profile's own
  `model_provider` pin, then the sidecar map.
- **`scripts/install-agents.sh`** — data-driven, dual-host, all-or-nothing installer.
  Preflights every destination, re-checks state immediately before each write, stages
  through a temporary file, and verifies byte-exactness afterwards. Refuses symlinked,
  non-regular, and modified destinations.
- **`scripts/inspect-agent-runtime.sh`** — emits only allowlisted routing fields from
  exactly one rollout file. Never prints prompts, messages, environment variables,
  tokens, or configuration.
- **`tests/run-tests.sh`** — 143 offline cases with synthetic session fixtures.
- **`scripts/verify.sh`** — release verification across manifests, pins, contract
  wording, cross-links, hygiene, and the behavioural suite.

### Corrected in a final conformance pass

- **`providers.md` invented a disagreement that does not exist.** It claimed the
  published config schema still advertised `responses | openai | aws-bedrock` and told
  the reader to trust the binary over it. The schema's `WireApi` is a `oneOf` with the
  single variant `responses`; schema and binary agree. A research summary I trusted was
  wrong and I propagated it. The file now states the stronger fact and cites the upstream
  discussion the binary itself links.
- **CI could not catch a broken manifest.** `claude plugin validate --strict` catches a
  trailing comma, a `keywords` value that became a string, or a `SKILL.md` whose
  frontmatter stopped parsing — but it needs the CLI, and CI deliberately runs without
  one, so all three would have reached a user before reaching a gate. `verify.sh` now
  validates manifest field types, component paths, marketplace sources, and frontmatter
  natively. Verified by corrupting each in turn with no CLI on `PATH`.
- **`openai.yaml` could not be regenerated by the official tool.** `short_description`
  was 83 characters against a 25-64 range the bundled generator enforces.
- **The Codex `defaultPrompt` now uses the namespaced `$fablewright:fablewright`**, since
  it seeds the marketplace composer and should be unambiguous. Human-facing docs keep the
  bare `$fablewright`.

### Added from a comparison against published plugin repositories

- **`/fablewright:setup`.** `preflight` diagnoses an install; it does not create one, so
  on a fresh machine every one of its checks correctly reported "not installed" and read
  as a wall of failures. `setup` bootstraps instead: it reports what is present, offers
  the install after showing a dry run, and states plainly that a machine without the
  Codex CLI is a reduced install rather than a broken one.
- **`scripts/bump-version.sh`.** The version appears in two manifests and six scripts and
  `verify.sh` fails if they disagree, which made a release six coordinated hand edits.
- **Authoring templates.** `hosts/codex/agents/TEMPLATE.toml.example` and
  `hosts/claude-code/agents/TEMPLATE.md.example` carry the clauses `verify.sh` enforces.
  Both use an `.example` suffix so neither is picked up as a real lane, which is checked.
- **The CI action is pinned to an immutable commit SHA**, not the floating `@v4` tag,
  with `dependabot.yml` to keep the pin from going stale. In a project whose thesis is
  *prove, do not assume*, a mutable third-party action was the one supply-chain hole
  `SECURITY.md` did not cover.
- Issue and pull-request templates that ask for the evidence this project runs on, and a
  security contact link that routes reports privately rather than into a public issue.

### Fixed before release, from an adversarial review

Five HIGH findings, all reproduced before being fixed and all now covered by tests.

- **The routing proof overstated what it checked.** `verified` was printed with the
  observed provider interpolated even when no provider was pinned and no comparison had
  run. The proof now separates `verified [...]` from `observed but NOT pinned, so NOT
  checked: ...`.
- **Effort was compared against one turn.** The inspector reports `effort` as the *last*
  turn and separately emits `efforts` precisely because effort varies per turn; the
  comparison read only the former. A thread running `low, low, max` under a `max` pin was
  reported as verified at `max`. Every turn is now compared, and the refusal names the
  off-pin value.
- **The profile parser was a line grep.** A `model_provider = "attacker-relay"` line
  placed inside the `developer_instructions` body was adopted as a genuine pin, and
  `model = "x" # comment` produced a corrupted `-m` argument. Parsing is now
  structure-aware — multiline-string state, `[table]` scope, trailing comments — and
  `verify.sh` uses the same parser so the verifier cannot be fooled by the same decoy.
- **`--report` was unsafe.** It followed symlinks, and under `set -e` a failed copy
  aborted the script *after* successful verification, discarding the result with an
  undocumented exit code. It now refuses symlinks and non-regular files, prints the
  report before writing it, and exits 64 on a write failure.
- **CI had never passed as configured.** `shellcheck --severity=warning` exited 1, and
  23 of the then-72 cases failed on a runner without the Codex and Claude Code CLIs,
  because dependency gates ran before argument handling. Gates moved to the point of use;
  the suite is now green with neither CLI installed, and CI asserts their absence rather
  than assuming it.

### Fixed in a second review round

- **A packet beginning with `-` or `---` aborted the wright.** The Claude Code CLI is
  option-parsing, and the packet was passed as a trailing positional with no `--`
  separator, so any packet opening with a markdown bullet, a `---` fence, or a diff
  header failed — and was misreported as an unreachable wright rather than a client-side
  parse error.
- **`--ephemeral` exited 0 while reporting `routing: waived`.** The printed string was
  honest; the exit status was not, so a caller gating on `$? -eq 0` could not tell a
  waived run from a proven one. Waived now exits **75**.
- **Only the final path component was symlink-checked.** A symlinked ancestor in
  `--target-dir` landed files somewhere other than the path the caller named, and the
  root guard matched only `/` and `//`, so `/.` and `///` slipped through. The target is
  now canonicalized before any guard runs; `/`, `/.`, `///` and any `..` component are
  refused, and a symlinked ancestor is resolved with the real destination reported.
- **The retained stderr log used a predictable path.** `${TMPDIR:-/tmp}/fablewright-cast-<pid>-stderr.log`
  written with `cp` could follow a pre-planted symlink on a shared host, and the content
  is raw runtime stderr. It now uses `mktemp`, which creates the file itself with
  `O_EXCL` and mode 0600.
- **`INSTALL PASSED` claimed exactness that a customization contradicted.** `--check` was
  honest about a customized lane; the install path was not.
- **Output assertions could pass on a failed run.** `expect_output` matched a substring
  of combined stdout and stderr without checking the exit status, and the failure path
  prints a `pinned: model=... effort=...` line that satisfied two of the pin assertions.
  Output assertions now check status; `expect_output_status` covers the failure paths.

One reported finding did not hold: a customized lane does **not** silently miss a
template update. `is_customized_with_provider` compares the stripped destination against
the current template, so a changed template classifies as `conflict` and is reported.

### Fixed in a third review round

- **A sandbox override could widen a lane's pin.** `--sandbox danger-full-access` was
  accepted for a reviewer pinned to `read-only`, waiving the only isolation the Codex
  reader has — and the run then reported `verified sandbox=danger-full-access`, true of
  what was asked for and false of the lane. An override may now only narrow.
- **An invalid model pattern was reported as a substituted wright.** `grep` exits 1 for
  "no match" and above 1 for "I could not evaluate that"; conflating them meant an
  unusable `FABLEWRIGHT_MODEL_PATTERN` produced an accusation of exactly the thing the
  check exists to detect. The two are now distinguished.
- **`--check-role` word-split and glob-expanded.** `--check-role '*'` expanded against
  the working directory, and a value containing a space silently became two roles. Role
  ids are now validated and pathname expansion is disabled while the list is read.
- **The routing command had no tool allowlist.** `/fablewright:route` told the model not
  to implement or delegate while inheriting the session's full tool set. It is now
  `Read, Grep, Glob`: the command that decides whether to delegate cannot start
  delegating.
- **The read command forbade its own first step.** `/fablewright:read` requires the
  wright to re-run the project's checks, but its allowlist permitted only git commands,
  so the reader would have been handed evidence the wright could not reproduce.
- **The sidecar provider map was documented at three different paths**, none of which
  was the real one. Corrected, with the repo-relative nature of the sidecar stated
  plainly: after installing profiles into `CODEX_HOME` the durable option is the
  profile's own `model_provider` line.

### Fixed in a fourth review round

- **`ensemble` had no rule for a mixed-family cast.** With a GPT lane and a GLM lane
  co-authoring one combined change set, neither shipped reader is cross-family to both,
  so `independence` would be half true on the route where seam risk is highest. Every
  cast lane in an `ensemble` must now come from one model family; mixed-family work is
  two sequential `full` routes. A deliberate override records `independence: partial` and
  names the lane the reader shares a family with. Model families are now a table, so
  "cross-family" is decidable rather than a judgement call.
- **A mid-run write failure left a partial install.** Preflight was all-or-nothing but
  the write loop was not: a failure at the mutation-time re-classify, the `ln` collision,
  or the `mv` left earlier roles written with no cleanup path. The run now records
  everything it creates and replaces, and undoes exactly that — never an earlier run's
  files — before exiting. `FABLEWRIGHT_TEST_FAIL_AFTER` exercises it; it can only abort a
  run and never skips a check or relaxes a refusal.
- **The route list in `/fablewright:route` disagreed with every other file.** It is
  cheapest-first precedence rather than the enumeration order used elsewhere, which was
  correct but stated nowhere.

One reported risk did not hold: `model_reasoning_effort = "max"` is real. A live `luna`
run reports `effort=max(all 1 turns)` and exits 0, so the stricter all-turns comparison
does not refuse every run of that lane.

### Added after reading the literature

- **Every lane carries an explicit stop condition.** Missing termination criteria account
  for a documented ~12% of multi-agent failures, and "keep going until it feels done" is
  not a criterion. Each implementer stops when its verification passes, when blocked, or
  when its owned file set is exhausted, and is told that finishing early with an honest
  `GAPS` entry beats an unbounded run. Each reader stops when it can justify a verdict.
  `verify.sh` fails the build if any profile omits one.

### Notes on evidence

Written against the real runtime rather than assumed from documentation:

- A Codex rollout file embeds **both** the subagent's `session_meta` and its parent's,
  so routing evidence is selected by thread id rather than by assuming one record.
- `agent_role` is `null` for a top-level thread such as one started by `codex exec`. A
  null role is reported, not refused; `--require-role` asserts a named custom agent.
- `effort` legitimately varies between turns of one thread, so `effort` reports the most
  recent turn and `efforts` lists every distinct value. `model` must not vary: a thread
  that changed model mid-flight has unverifiable routing and is refused.
- `sandbox_policy` and `permission_profile` appear both as an object carrying `type` and
  as a bare string. Both shapes are handled.
- A Codex custom-agent TOML **does** accept `model_provider`, confirmed by schema probe
  against the shipped binary with a positive control (`cwd`, `provider`, and a nonsense
  key are all rejected; `model_provider`, `model_reasoning_effort`, `sandbox_mode`,
  `developer_instructions`, `approval_policy`, and `tools` are accepted). The provider
  therefore lives in the lane profile alongside the model pin, and the installer accepts
  exactly one appended `model_provider` line as a CUSTOMIZED state that passes `--check`
  and is never overwritten. The line must be a real TOML key: one placed inside the
  `developer_instructions` string would strip back to a byte-exact template while having
  altered what the worker is told, so position is checked by counting the `"""`
  delimiters that precede it.
- `wire_api` accepts only `responses` on Codex CLI 0.153.0. `chat` returns "is no longer
  supported" and `openai` returns "unknown variant". The published config schema agrees
  rather than conflicting: its `WireApi` is a `oneOf` carrying the single variant
  `responses`. An endpoint that speaks only chat-completions cannot serve a Codex lane on
  this version.
